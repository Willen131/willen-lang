# Willen 开发指南

面向第一次使用 Willen 语言的人。完整的语言定义见
[《Willen 语言规范》](Willen语言规范.md)，本文只讲**怎么用起来**。

---

## 1. 安装与运行

### 构建

需要 `g++`（支持 C++17）与 Git Bash。

```bash
git clone git@github.com-Willen131:Willen131/willen-lang.git
cd willen-lang
bash build.sh
```

构建产物是单个 `willen.exe`，已静态链接，不依赖任何运行库 DLL，
可以直接拷贝到别的机器上运行。

### 四个命令

```bash
./willen run  <文件.wl>     # 执行脚本
./willen repl               # 交互式解释器
./willen test <目录>        # 运行黑盒测试集
./willen lex  <文件.wl>     # 打印词法单元（调试用）
./willen ast  <文件.wl>     # 打印语法树（调试用）
```

### 第一个程序

新建 `你好.wl`：

```willen
打印("你好，世界！")
```

```bash
./willen run 你好.wl
```

```
你好，世界！
```

### 交互式试用

不想建文件时，用 `repl`：

```
$ ./willen repl
Willen 交互式解释器。输入 退出 结束，Ctrl+D 亦可。
> 设 甲 = 42
> 甲 * 2
84
> 函数 平方(x) { 返回 x * x }
> 平方(7)
49
> 退出
```

变量与函数定义在整个会话内有效；花括号没配平时会自动续行，
所以函数和循环可以分行输入。

## 2. 编辑器配置

**源文件必须保存为 UTF-8 无 BOM。** 这是唯一一条硬性环境要求。

### VS Code

在项目根目录建 `.vscode/settings.json`：

```json
{
  "files.encoding": "utf8",
  "files.eol": "\n"
}
```

### 记事本

另存为时**编码选 `UTF-8`**，不要选 `ANSI`。

### 如果存错了会怎样

如果文件被存成 GBK/ANSI，运行时会看到：

```
第 1 行：源文件编码不是 UTF-8，请以 UTF-8 无 BOM 格式保存
```

这条提示会救你——否则你看到的将是一连串莫名其妙的「无法识别的字符」。

## 3. 五个渐进示例

### 示例一：变量与运算

```willen
设 半径 = 2.5
常量 圆周率 = 3.14159
设 面积 = 圆周率 * 半径 * 半径

打印("半径 {半径} 的圆面积是 {面积}")
```

```
半径 2.5 的圆面积是 19.634937
```

要点：
- `设` 声明变量，`常量` 声明不可重新赋值的常量
- `{表达式}` 是模板插值，可以直接放进字符串
- `半径` 是 5.0 所以结果是小数；若写 `设 半径 = 5`，`面积` 也会是小数
  （因为与小数相乘会提升）

### 示例二：条件与循环

```willen
函数 评级(分数) {
    如果 (分数 >= 90) { 返回 "优秀" }
    否则如果 (分数 >= 60) { 返回 "及格" }
    否则 { 返回 "不及格" }
}

遍历 (分数 在 [95, 72, 45]) {
    打印("{分数} 分：{评级(分数)}")
}

设 倒计时 = 5
当 (倒计时 > 0) {
    打印("倒计时 {倒计时}")
    倒计时 = 倒计时 - 1
}
```

```
95 分：优秀
72 分：及格
45 分：不及格
倒计时 5
倒计时 4
倒计时 3
倒计时 2
倒计时 1
```

要点：
- **条件的括号是必须的**：`如果 (分数 >= 90)`，不能写成 `如果 分数 >= 90`
- `否则如果` 可以连写多级
- `遍历` 的括号可以省略：`遍历 分数 在 [...]` 也合法

### 示例三：数组与统计

```willen
设 成绩 = [85, 92, 78, 96, 61]

设 总分 = 0
遍历 (分 在 成绩) { 总分 = 总分 + 分 }

设 最高 = 成绩[0]
遍历 (分 在 成绩) {
    如果 (分 > 最高) { 最高 = 分 }
}

打印("共 {成绩.长度} 人")
打印("总分 {总分}，平均 {总分 / 成绩.长度}")
打印("最高 {最高}")

设 副本 = 成绩.切片(0, 成绩.长度)
副本.排序()
打印("升序：{副本}")
```

```
共 5 人
总分 412，平均 82
最高 96
升序：[61, 78, 85, 92, 96]
```

要点：
- `.长度` 是属性，也可以写 `长度(成绩)`
- `.切片(0, 长度)` 是**复制**数组的常用写法（切片是左闭右开）
- 排序是原地操作，所以先切片复制，避免改到原数组

### 示例四：递归

```willen
函数 阶乘(甲) {
    如果 (甲 <= 1) { 返回 1 }
    返回 甲 * 阶乘(甲-1)
}

函数 斐波那契(甲) {
    如果 (甲 < 2) { 返回 甲 }
    返回 斐波那契(甲-1) + 斐波那契(甲-2)
}

打印("5! = {阶乘(5)}")
遍历 (序 在 0..9) {
    打印("斐波那契第 {序} 项 = {斐波那契(序)}")
}
```

```
5! = 120
斐波那契第 0 项 = 0
斐波那契第 1 项 = 1
...
斐波那契第 9 项 = 34
```

要点：
- `0..9` 生成 `[0, 1, …, 9]`，**含 9**（闭区间）
- 递归深度上限 200 层。写错成无限递归会得到明确提示，而不是崩溃：

  ```
  第 2 行：递归层数过深（上限 200），请检查是否存在无限递归
  ```

### 示例五：结构体

```willen
结构 商品 { 名称, 单价, 数量 }

设 购物车 = [
    商品{名称: "苹果", 单价: 5, 数量: 3},
    商品{名称: "香蕉", 单价: 3, 数量: 5}
]

函数 总价(车) {
    设 合计 = 0
    遍历 (项 在 车) {
        合计 = 合计 + 项.单价 * 项.数量
    }
    返回 合计
}

遍历 (项 在 购物车) {
    打印("{项.名称}：{项.单价} 元 × {项.数量}")
}
打印("合计 {总价(购物车)} 元")
```

```
苹果：5 元 × 3
香蕉：3 元 × 5
合计 30 元
```

要点：
- 结构体定义只需字段名列表
- 构造时用 `结构名{字段: 值, ...}`，未提供的字段默认为 `空`
- 结构体是**引用语义**，函数内修改会影响调用方

## 4. 风格约定

语言本身不强制风格，以下是推荐做法：

| 项目 | 建议 |
|---|---|
| 缩进 | 4 个空格 |
| 命名 | 用能读懂的中文：`学生表` 优于 `arr1` |
| 常量 | 能不变的用 `常量` 声明 |
| 函数 | 一个函数做一件事，超过 30 行考虑拆分 |
| 注释 | 用 `#`，解释「为什么」而不是「做了什么」 |
| 分号 | 省略不写（语法上可选） |
| 括号 | `如果`/`当` 的括号必须写；`遍历` 的括号建议写，更整齐 |

## 5. 常见错误排查

### 一、中文显示成乱码

**原因**：源文件不是 UTF-8。

**排查**：用编辑器确认编码；或在命令行看文件头：

```bash
head -c 16 你的文件.wl | od -c
```

若开头是 `\357 \273 \277`（BOM）或中文字节不符合 UTF-8 规律，就是编码问题。

### 二、`未定义的变量「甲」`

三种可能：

1. **拼写不一致**——中文变量名容易打字差异，检查每一处
2. **作用域不对**——变量定义在某个 `{ }` 块内，块外看不见
3. **函数内引用**——函数看不见调用者的局部变量，只能看见全局

```willen
函数 甲() {
    设 局部 = 1
}
打印(局部)      # 报错：未定义的变量「局部」
```

### 三、`如果 的条件必须用括号包围`

这是 Willen 与其他语言最大的书写差异。**条件必须加括号**：

```willen
如果 甲 > 0 { ... }        # ✗ 报错
如果 (甲 > 0) { ... }      # ✓
```

原因见规范 §3.4：不加括号时 `甲 {` 与结构字面量 `点{横: 1}` 无法区分。

### 四、字符串里的花括号

花括号在字符串里是**特殊字符**（用来做插值）：

```willen
打印("结果是 {甲}")        # 插值
打印("集合 {1, 2}")        # ✗ 报错：模板插值表达式未闭合
```

想输出字面花括号，有两种写法：

```willen
打印("集合 {{1, 2}}")      # 双写
打印("集合 \{1, 2\}")      # 转义
```

### 五、`!` 不是逻辑非

```willen
如果 (!真) { ... }         # ✗ 报错
如果 (非 真) { ... }       # ✓
```

`!` 只出现在 `!=` 里。

### 六、整数除法的意外结果

```willen
打印(7 / 2)         # 3，不是 3.5
打印(7.0 / 2)       # 3.5
打印(7 / 2.0)       # 3.5
```

需要小数结果时，让其中一个操作数写成小数。

### 七、以为 `0` 或空数组是「假」

```willen
如果 (长度(数列) > 0) { ... }    # ✓ 显式判断
如果 (数列) { ... }              # 空数组也是真，不会按预期跳过
```

只有 `假` 和 `空` 是假。

### 八、数组赋值后改一个影响另一个

```willen
设 甲 = [1, 2]
设 乙 = 甲
乙.追加(3)
打印(甲)      # [1, 2, 3]——甲也变了
```

数组是引用语义。要独立副本用切片：

```willen
设 乙 = 甲.切片(0, 甲.长度)
```

### 九、中文字符串取长度结果翻倍

```willen
打印(长度("你好"))     # 6，不是 2
```

字符串按字节操作，每个汉字 3 字节。详见规范 §4.10。

### 十、构建失败但没有任何错误输出

如果 `bash build.sh` 失败却一个字都不显示，多半是系统临时目录
`%TEMP%` 里文件堆积过多，导致编译器前端无法创建临时文件而静默退出。
本项目的 `build.sh` 已固定使用项目内的 `.build-tmp/` 目录规避此问题；
若仍遇到，清理系统临时目录即可。

## 6. 写测试

项目自带黑盒测试框架。给你的 Willen 程序写测试只需两步：

**第一步**：写一个 `.wl` 文件，用测试库提供的断言函数。

```willen
# 我的测试.wl
函数 平方(甲) { 返回 甲 * 甲 }
断言等于(平方(3), 9, "3 的平方")
断言等于(平方(0), 0, "0 的平方")
测试汇总()
```

**第二步**：把期望输出写进同名 `.expected` 文件。

```
全部 2 个断言通过
```

然后运行：

```bash
./willen test .
```

可用的断言函数（由 `tests/测试库.wl` 提供，运行器自动加载）：

| 函数 | 说明 |
|---|---|
| `断言(条件, 描述)` | 条件为真则通过 |
| `断言等于(实际, 期望, 描述)` | 两值深度比较相等则通过 |
| `断言不等(实际, 期望, 描述)` | 两值不相等则通过 |
| `测试汇总()` | 输出统计，放在文件末尾 |

**验证运行时错误**：把期望文件命名为 `.expected_err`（内容写错误信息），
运行器会检查脚本**确实失败**且错误信息匹配：

```
# 我的测试_除零.wl
打印(1 / 0)
```

```
# 我的测试_除零.expected_err
第 2 行：除数不能为零
```

> 注意：`.expected` 必须**手写**，不要用程序输出直接生成。
> 自动生成的期望只是把当前行为抄了一遍，无论对错都会通过，失去了测试的意义。
