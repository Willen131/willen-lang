# 二、语言定位

## Willen 是什么

**中文关键字的类 C 脚本语言**：动态类型、大括号分块、
无闭包、无异常、无类。

```willen
结构 点 { 横, 纵 }

函数 距离平方(甲, 乙) {
    设 横差 = 甲.横 - 乙.横
    设 纵差 = 甲.纵 - 乙.纵
    返回 横差 * 横差 + 纵差 * 纵差
}

设 甲 = 点{横: 0, 纵: 0}
设 乙 = 点{横: 3, 纵: 4}
打印("距离平方 = {距离平方(甲, 乙)}")
```

## 四大特色

| 特色 | 例子 | 说明 |
|---|---|---|
| **中文关键字** | `设` `如果` `遍历` `重复 5 次` | 21 个，无英文别名 |
| **自然语言式循环** | `重复 N 次 { }` | 量词 `次` 夹住表达式，主流通用语言中独一无二 |
| **闭区间范围** | `0..9` 含 9，共 10 个 | 与 Rust/Kotlin 的同形语法**语义相反** |
| **条件强制括号** | `如果 (甲 > 0) { }` | 消除与结构字面量的歧义 |

# 三、与现存语言的差异

## 诚实对照

| Willen 特性 | 相似者 | 关键差异 |
|---|---|---|
| 中文关键字 | 易语言 | 易语言用 `如果…那么…结束如果` 闭合块；Willen 用大括号 |
| 范围 `0..9` | Rust、Kotlin | **它们是左闭右开（不含 9），Willen 是闭区间** |
| 条件必须加括号 | C、Java | Go / Rust / Swift 都**不要求**（而它们没有结构字面量语法） |
| 字符串模板 | Python f-string | 语法相近；Willen 在**词法阶段**完成切分 |

## 整体组合是独有的

以下几条**同时成立**，任何现存语言都不具备：

1. `重复 N 次 { … }` —— 自然语言量词式循环
2. `0..N` 是**闭区间**
3. 中文关键字 + 强制括号 + 闭区间范围 + 模板插值四者并存
4. `否则如果` 不引入独立节点，而是解析为嵌套的 `如果`

**单个特性可能有先例，组合没有。**

# 四、完整示例

## 词频统计

```willen
函数 词频统计(文本) {
    设 词表 = 文本.分割(" ")
    设 统计 = []
    遍历 (词 在 词表) {
        如果 (词 == "") { 继续 }
        设 已见 = 假
        遍历 (项 在 统计) {
            如果 (项[0] == 词) {
                项[1] = 项[1] + 1
                已见 = 真
                跳出
            }
        }
        如果 (非 已见) { 统计.追加([词, 1]) }
    }
    返回 统计
}
```

用到：函数、字符串方法、数组方法、嵌套数组、三种循环、跳转、
模板插值、中文错误信息所依赖的行号跟踪。

## 实际输出

```
共 3 个不同的词，前 3 名如下：
  苹果 出现 3 次
  香蕉 出现 2 次
  樱桃 出现 1 次
```

# 七、实现要点（一）

## 中文关键字是怎么实现的

`lexer.cpp` 里只有一行关键：

```cpp
return std::isalpha(u) || c == '_' || u >= 0x80;
```

UTF-8 把一个汉字编码成 3 个字节，**每个字节都 ≥ 0x80**。
把标识符规则放宽到接受非 ASCII 字节后，`设`、`斐波那契` 就和
`if`、`foo` 一样被当作完整标识符读入，之后查同一张哈希表。

**结论：中文关键字不需要任何特殊处理，本质是「标识符规则放宽 + 哈希表」。**

## 表达式优先级靠调用层次表达

`parser.cpp` 里没有优先级数字表，而是一条调用链：

```
赋值 → 或 → 且 → 相等 → 比较 → 范围 → 加减 → 乘除模 → 一元 → 后缀 → 基本
```

低优先级运算符位于调用栈外层，因此天然后结合。
**读代码时看到的调用链，就是优先级表本身。**

# 八、实现要点（二）

## 条件的括号是强制的

`如果 甲 { }` 里的 `甲 {` 与结构字面量 `点{横: 1}` 的写法**完全一致**，
解析器无从区分。强制括号把这个歧义在语法层面直接消除，
递归下降因此不需要任何回溯。

这不是理论担忧——实现时真的踩到过：报错后若继续按原样解析，
`甲 {` 会被当成结构字面量，进而报出一串与真正原因无关的级联错误。

## 模板字符串在解析期降解

1. **词法阶段**：`"你好，{名字}！"` 切成「文本 / 插值 / 文本」片段序列
2. **解析阶段**：插值片段被**递归送进词法 + 语法分析器**，变成子 AST 节点

**运行时求值模板只剩字符串拼接，完全不碰字符串解析。**

## 控制流用返回值传递，不用异常

`exec` 返回 `Flow` 枚举（`Normal / Break / Continue / Return`）。
循环消费 `Break` 与 `Continue`，函数体消费 `Return`——
**所以 `跳出` 不会穿出函数边界。**

# 十、性能测试（10 分）

## 公平性保障（六条）

两语言性能对比极容易做成不公平的，因此逐条交代：

1. **算法完全一致**——逐行对应，不存在一边用内置排序一边手写冒泡
2. **输入数据完全一致**——同一个自实现的线性同余生成器，不碰内置随机数
3. **结果逐字节校验**——两语言输出一致才计入
4. **3 次取中位数**——降低系统噪声
5. **计时在进程外部**——不依赖任何语言自身的计时函数
6. **同机连续测量**——避免环境漂移

## 五组基准

`fib`（函数调用）· `loop`（循环与变量）· `sort`（数组下标）·
`str`（字符串复制）· `maze`（综合场景）

# 十一、性能结果与优化

## 三版数据

| 基准 | v1 基线 | v2 槽位化 | v3 +kind分发 | v1→v3 |
|---|---:|---:|---:|---:|
| `fib` | 0.906 | 0.840 | **0.318** | 2.9× |
| `loop` | 1.693 | 1.491 | **0.205** | 8.3× |
| `sort` | 13.375 | 7.635 | **0.938** | **14.3×** |
| `str` | 0.835 | 0.842 | 0.727 | 1.1× |
| `maze` | 0.254 | 0.239 | **0.044** | 5.8× |

**相对 CPython 的倍率：从 8.6–64.5 倍收敛到 2.0–9.9 倍。**

## 两次优化

**一、变量槽位化**：解析期把局部变量绑定成槽位下标，运行期按 `vector`
寻址，取代原来的字符串哈希。顺带让作用域链整个消失。

**二、求值分发改用 kind 枚举**：原实现用一长串 `dynamic_cast` 判断节点类型，
每求值一个节点要尝试十几个类型；改用 `switch` 后只剩一次跳转。

## 一个值得讲的过程

做完槽位化后 `fib` 只快了 8%——**正是这个「低于预期」的信号**，
促使我去查真正的热点，才发现了 `dynamic_cast` 分发的问题，
随后拿到 5–8 倍的提升。

**如果当时因为"优化已经有效果了"而收手，就会错过它。优化必须由测量驱动。**

## 诚实呈现

- `str` 几乎没改善——它的热点是字符串复制（O(n²)），与两次优化都无关。
  **没有改善的项恰好印证优化是有的放矢的。**
- 最大短板是**函数调用**（每次新建帧），这是后续方向。

# 十三、Agent 开发与验证

## 三次实验

| 轮次 | 任务 | 结果 |
|---|---|---|
| 一 | 25 行猜数字 | 首轮通过，八条规则零违反 |
| 二 | 206 行迷宫 | 首轮通过，但发现 **8 处指南空白**（5 处被规避） |
| 三 | 321 行迷宫 + 新功能 | 首轮通过，**4 个规避行为全部消失** |

## 第二轮的关键发现

Agent 首轮零错误，但读它的自述会发现：**它是靠保守策略绕过去的**。

| 疑问 | 真实答案 | Agent 怎么做的 |
|---|---|---|
| 函数能读写顶层变量吗 | 能 | **回避**：用单元素数组当"可变盒子"传状态 |
| `!=` 存在吗 | 存在 | **回避**：全写成 `非 (甲 == 乙)` |
| `..` 与 `-` 谁优先 | `..` 更低 | **回避**：完全不用范围运算符 |

**它没出错，但付出了不必要的复杂度。**

## 修订被证实有效

补上运算符表、作用域规则、类型范围、字符串拼接四节后，重做实验：

| 观测点 | 第一轮 | 第三轮 |
|---|---|---|
| 共享随机状态 | 可变盒子 | ✅ 函数内直接改顶层变量 |
| 范围运算符 | 完全不用 | ✅ 用了 `0..(尺寸-1)` |
| `!=` | 全写成 `非 (…)` | ✅ 用了裸比较 |

**指令中唯一改变的是指南内容，写法随之改变——排除了"模型随机性"的解释。**

## 一条方法论结论

**「零错误」这个指标会掩盖「指南没说清楚」这个问题。**

只看通过率就会以为指南够好；**只有读 Agent 自述的不确定之处，
才能看见那些被绕过去的空白。**

| 问题 | 根因 | 修法 |
|---|---|---|
| 编译失败但**零输出** | 系统 `%TEMP%` 堆积 2360 个文件，编译器前端无法创建临时文件而静默退出 | `build.sh` 固定用项目内临时目录 |
| 中文路径完全不可用 | ① `u8path` 依赖 locale ② **Windows 传给 main 的 argv 本身就是 GBK** | 绕开 `std::filesystem`，直接用 Windows API 转换 |
| `repl` 里定义函数调不到 | 函数表存裸指针，而 repl 的语法树出作用域即销毁 | 解释器接管语法树所有权 |
| 测量脚本报告"结果不一致" | Python 输出 CRLF，Willen 输出 LF | 比对前统一行尾 |

## 一条共同的经验

**崩溃消失 ≠ 功能可用。**

中文路径那个问题有两层根因：修掉第一层后不再崩溃了，
但文件仍然打不开。**如果当时收手，就会留下一个"看起来没问题、
实际用不了"的功能。**

# 十七、总结

## 交付物

| 评分项 | 分值 | 产出 |
|---|---|---|
| 解释器实现 | 20 | `src/` 12 个文件约 3000 行 + `willen.exe` |
| 自动测试脚本 | 20 | 12 模块 247 断言 + 8 错误用例 + 自举断言库 |
| 性能测试 | 10 | 5 组基准 × 双语言 × 3 版本 + 完整报告 |
| 语法说明与指南 | 20 | 语言规范 851 行 + 开发指南 + AI 指南 + Skill |
| Agent 开发应用 | 30 | `apps/迷宫.wl` 321 行 + 三步实验的开发记录 |

## 三条我认为最有价值的经验

**一、测试集是改代码的底气。**
性能优化动了核心执行路径，之所以敢动，是因为每步之后跑 19 个测试文件
（247 断言）都通过。

**二、优化必须由测量驱动。**
槽位化后 `fib` 只快 8% 这个"低于预期"的信号，直接指向了真正的热点
（`dynamic_cast` 分发），随后拿到 5–8 倍提升。

**三、用 Agent 的实际行为检验文档，比通读文档有效得多。**
Agent 会把"资料没写"精确暴露成"我不得不绕路"，
而通读文档只会得出"该写的都写了"的错觉。

## 展望

- **最大的性能短板是函数调用**（每次新建帧），优化它应能再进一步
- **字符串按字节操作**是已知限制，若需按字符处理中文可后续扩展
- **可考虑编译为字节码**，替代当前的 AST 树遍历
