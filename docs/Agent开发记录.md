# Agent 开发记录

记录使用编程 Agent 开发 Willen 程序的过程：提供了什么上下文、
Agent 产出了什么、验证结果如何、以及从中学到了什么。

---

## 记录一：验证 AI 开发指南的有效性

**日期**：2026-10-09

**目的**：检验 `docs/AI开发指南.md` 与 `skills/willen/SKILL.md` 是否足以让
一个**完全不了解 Willen 的编程 Agent** 首轮写出可运行的代码。

### 实验设计

| 项 | 设置 |
|---|---|
| Agent 类型 | 通用编程 Agent（general-purpose） |
| 提供的上下文 | **仅** `skills/willen/SKILL.md` 的正文内容 |
| 明确禁止 | 读取项目中的任何其他文件（`docs/`、`tests/`、`src/`、`examples/`） |
| 任务 | 猜数字游戏：随机数 1–100、循环输入、大小提示、计数、非法输入处理 |
| 规模要求 | 不少于 25 行（不含空行），带中文注释 |

**为什么必须禁止读其他文件**：项目里的 `tests/` 有 12 个模块的测试集，
`docs/Willen语言规范.md` 有完整规范——Agent 若读了它们，就无法判断结果
是「指南有效」还是「资料足够多」。**只有把资料限制到指南本身，
测出来的才是指南的有效性。**

### Agent 的产出

`apps/猜数字.wl`，62 行（要求 25 行）：

```willen
# 猜数字游戏
# 程序先随机生成一个 1 到 100 的目标数，然后不断让玩家猜测，
# 每次给出「大了」「小了」的提示，猜中后统计并输出猜测次数。

# 判断一个字符串是否全部由数字字符组成。
# 因为 整数() 遇到非数字内容会直接报错，所以必须先自行检查。
函数 是数字串(甲) {
    如果 (长度(甲) == 0) { 返回 假 }
    设 数字表 = "0123456789"
    设 游标 = 0
    当 (游标 < 长度(甲)) {
        如果 (非 数字表.包含(甲.字符(游标))) {
            返回 假
        }
        游标 = 游标 + 1
    }
    返回 真
}

# 随机数两端都包含，所以 随机数(1, 100) 就是 1 到 100 之间的整数
设 目标 = 随机数(1, 100)

# 有效猜测次数，非法输入不计入
设 次数 = 0

# 主循环：反复提示输入，直到猜中才跳出
当 (真) {
    设 行 = 输入("请输入 1-100 的数字：")

    # 去掉首尾空白，避免玩家多打了空格导致误判
    设 文本 = 行.去空白()

    # 情况一：不是纯数字，提示后重新输入，次数不增加
    如果 (非 是数字串(文本)) {
        打印("输入的不是数字，请重新输入")
        继续
    }

    设 猜 = 整数(文本)

    # 情况二：数字超出了 1 到 100 的范围，同样视为无效输入
    如果 (猜 < 1 或 猜 > 100) {
        打印("数字超出范围，请输入 1-100 的数字")
        继续
    }

    # 到这里才算一次有效猜测
    次数 = 次数 + 1

    如果 (猜 > 目标) {
        打印("大了")
    } 否则如果 (猜 < 目标) {
        打印("小了")
    } 否则 {
        打印("猜中了！")
        跳出
    }
}

# 猜中后结束，输出总次数
打印("你一共猜了 {次数} 次")
```

### 验证过程与结果

| 检查项 | 命令 | 结果 |
|---|---|---|
| 语法正确 | `willen ast apps/猜数字.wl` | 通过，无语法错误 |
| 基本运行 | 喂入 1..100 | 正常猜中并退出，退出码 0 |
| 非法输入（非数字） | 先喂 `abc` | 提示「输入的不是数字，请重新输入」 |
| 非法输入（超范围） | 再喂 `200` | 提示「数字超出范围，请输入 1-100 的数字」 |
| 计数准确性 | 上述非法输入 | 均未计入有效次数 |

**首轮通过率：1 / 1 = 100%**

### 指南硬性规则的遵守情况

逐条核对指南第 1 节的八条规则：

| # | 规则 | 是否遵守 |
|---|---|---|
| 1 | 关键字全中文 | ✅ 无一处英文关键字 |
| 2 | 标点全半角 | ✅ |
| 3 | 条件加括号 | ✅ 每个 `如果` / `当` 都有括号 |
| 4 | 字符串里的花括号处理 | ✅ 未出现字面花括号，未触发 |
| 5 | 逻辑非用 `非` | ✅ 用了 `非 数字表.包含(...)` |
| 6 | 方法名中文 | ✅ `.包含()` `.字符()` `.去空白()` |
| 7 | 无嵌套函数定义 | ✅ 函数在顶层 |
| 8 | 无异常机制 | ✅ 用主动检查代替 |

**八条全中，零违反。**

### 值得记录的细节：Agent 写出了指南没教、但更好的写法

我在指南 §4.6 给的输入校验模板是逐字符比较：

```willen
遍历 (字 在 文本) {
    如果 (字 < "0" 或 字 > "9") { 返回 空 }
}
```

Agent 写的是：

```willen
设 数字表 = "0123456789"
当 (游标 < 长度(甲)) {
    如果 (非 数字表.包含(甲.字符(游标))) { 返回 假 }
    游标 = 游标 + 1
}
```

用字符串的 `包含` 与 `字符` 做成员判断。**这比我的模板更稳**——
逐字符比较依赖字符串比较的语义，而 `包含` 是在一个明确的字符集里查找，
意图更直接、边界更清楚。

这说明指南没有限制住 Agent 的表达：它能在规则之内自行选出更好的实现方式。
这是好现象——**指南约束的是「不能写什么」，而不是「必须怎么写」。**

### 结论

**指南有效。** 一个没有任何 Willen 先验知识的 Agent，仅凭 `SKILL.md`
就首轮写出了语法正确、功能完整、边界处理妥当的代码。

这条结论有实际意义：它说明 Willen 的语法设计对机器足够友好——
规则数量少、上下文无关、无歧义，因此能被准确描述，也能被准确实现。

### 后续可改进之处

指南 §4.6 可以补上 Agent 的这个写法作为推荐模板（本记录已保留该写法）。

## 记录二：用 Agent 开发迷宫应用（复杂程序）

**日期**：2026-10-11

**目的**：记录一验证了指南对 25 行的简单程序有效。
本次检验它在 **150 行以上的复杂程序**上是否同样够用。

### 实验设计

| 项 | 设置 |
|---|---|
| Agent 类型 | 通用编程 Agent |
| 提供的上下文 | **仅** `skills/willen/SKILL.md` 的内容 |
| 明确禁止 | 读取项目中的任何其他文件 |
| 任务 | 12×12 迷宫：递归回溯生成 + BFS 求最短路 + 字符画渲染 |
| 规模要求 | 不少于 150 行（不含空行），带中文注释 |
| 埋设的约束 | ① 递归不超过 150 层；② 自实现线性同余生成器且固定种子；③ 提示遍历二维数组时得到的是行 |

### 产出与验证

`apps/迷宫.wl`，219 行（非空 206 行，要求 ≥150）。

**独立验证结果**（不依赖 Agent 的自述）：

| 检查项 | 命令 | 结果 |
|---|---|---|
| 语法正确 | `willen ast apps/迷宫.wl` | ✅ 通过 |
| 运行 | `willen run apps/迷宫.wl` | ✅ 退出码 0 |
| 可复现 | 连续两次运行并 `diff` | ✅ 输出逐字节一致 |
| 渲染正确 | 目视检查 | ✅ 路径从「起」连续贯通到「终」 |

**首轮通过，零语法错误。**

### 关键发现：首轮成功 ≠ 指南完备

Agent 在报告中主动列出了**八处「对语言规则的不确定」**，并说明它如何应对。
逐条验证真实答案后，发现**这八条 SKILL.md 一条都没写**：

| # | Agent 的疑问 | 真实答案 | Agent 的应对 |
|---|---|---|---|
| 1 | 函数能否读写顶层变量 | ✅ 能 | **回避**：改用单元素数组当「可变盒子」传递随机状态 |
| 2 | 循环体内 `设` 会冲突吗 | ✅ 不会，每轮新建 | 照常使用，实测无问题 |
| 3 | 字符串能否用 `+` 拼接 | ✅ 能 | **回避**：改用数组的 `.连接("")` 拼渲染行 |
| 4 | `!=` 存在吗 | ✅ 存在 | **回避**：全部写成 `非 (甲 == 乙)` |
| 5 | `..` 与 `-` 的优先级 | ✅ `..` 更低 | **回避**：完全不用范围运算符，全改成 `当` 计数循环 |
| 6 | `且` 与比较的优先级 | ✅ `且` 更低 | **回避**：每个比较两侧都加括号 |
| 7 | 整数位宽 | ✅ 64 位有符号 | **规避风险**：特意选小模数，让中间乘积落在 32 位内 |
| 8 | `.连接` 传空分隔符 | ✅ 可用 | 照常使用，实测无问题 |

**八条中有五条被 Agent 主动规避掉了。**

它没出错，但**付出了不必要的复杂度**：用单元素数组当可变盒子共享随机状态，
而 Willen 的顶层变量本来就能被函数直接读写；完全不用范围运算符，
把 `0..行数-1` 写成 `当` 计数循环；每个简单比较都套上括号。

这些规避不是浪费——**在资料没有明确说明的情况下，保守是正确策略**。
但它说明 SKILL.md 存在系统性空白：**它擅长说「不能写什么」
（八条禁止规则零违反），却很少说「允许写什么」。**

### 据此修订指南

在 `skills/willen/SKILL.md` 与 `docs/AI开发指南.md` 中补上四节：

| 补充内容 | 针对的疑问 |
|---|---|
| **运算符表与优先级** | #4 `!=`、#5 `..` 优先级、#6 `且` 优先级 |
| **作用域规则**（顶层变量全局可读写） | #1、#2 |
| **类型与数值范围**（整数 64 位） | #7 |
| **字符串拼接**（`+` 的用法） | #3 |

其中作用域一节特别注明：**不需要为了共享状态把变量包进数组**——
这正是 Agent 那个「可变盒子」手法所绕开的点。

### 结论

- 复杂程序（206 行、涉及二维数组、队列、多函数协作）**首轮零错误通过**
- 但首轮成功**不等于指南完备**：Agent 是靠保守规避达成的，
  代价是不必要的复杂度
- **「零错误」这个指标会掩盖「指南没说清楚」这个问题**——
  只有读 Agent 自述的不确定之处，才能看见空白

这条结论对 Day 16 的应用完善有直接指导意义：
修订后的指南应能让 Agent 写出更简洁的代码（不再需要可变盒子之类的规避）。

## 记录三：修订指南后的第二轮验证

**日期**：2026-10-12

**目的**：验证记录二末尾那个推测——**指南修订后，Agent 是否会写出更简洁的代码**。
这是一个可证伪的预测：如果修订有效，Agent 的规避行为应该消失。

### 实验设计

与记录二完全相同，**唯一的变量是指南**：

| 项 | 设置 |
|---|---|
| 提供的上下文 | **仅修订后的 `skills/willen/SKILL.md`**（新增了运算符表、作用域、类型范围、字符串拼接四节） |
| 任务 | 12×12 迷宫，另加统计输出与**第二种渲染模式**（只显示路径形状） |
| 规模要求 | 不少于 200 行（比上一轮更高） |

### 结果对比

`apps/迷宫.wl`，354 行（非空 321 行，要求 ≥200）。
独立验证：语法正确、退出码 0、两次运行输出一致。

**四个观测点全部发生改变**：

| 观测点 | 第一轮（旧指南） | 第二轮（修订后） |
|---|---|---|
| 共享随机状态 | 用单元素数组当「可变盒子」 | ✅ **函数内直接改顶层变量**（第 35 行） |
| 范围运算符 | 完全不用，改 `当` 计数循环 | ✅ 用了 `0..(尺寸 - 1)` |
| `且` 连接比较 | 每个比较都套括号 | ✅ 用了裸比较 |
| 字符串拼接 | 用 `.连接("")` | ✅ 用了 `+` |

**修订有效，预测得到证实。** 指令中唯一改变的是指南内容，
Agent 的写法随之改变——这排除了「模型随机性」的解释。

### 但仍暴露了两处新空白

Agent 这次报告了六处不确定，其中两处是**上一轮没暴露的**：

| # | 疑问 | Agent 的应对 | 真实答案 |
|---|---|---|---|
| 1 | 数组字面量能写 `[a, b]` 吗（指南只给过 `[]`） | **回避**：全程用「整数编码坐标」（`行*尺寸+列`）代替坐标数组 | ✅ 能，元素可为任意类型 |
| 2 | `且` / `或` 会短路吗 | **回避**：担心负下标，把边界判断全改成嵌套 `如果` | ✅ 会短路，可放心写 `行 > 0 且 网格[行-1][列] == 0` |

**第 2 条尤其值得注意**：短路求值是**保证边界检查正确性的关键机制**。
不知道它，Agent 就只能写更啰嗦的嵌套判断——代码仍然正确，但可读性下降。

### 据此再次修订指南

补上两节：**逻辑运算会短路**（附边界检查的实用写法）、
**数组的构造与二维数组**（含非空字面量、逐行新建的必要性）。

### 结论：指南的改进是一个可循环的过程

三轮实验形成了一个完整的闭环：

```
第一轮（简单程序）→ 首轮通过  → 以为指南够用
第二轮（复杂程序）→ 首轮通过  → 但发现 8 处空白，5 处被规避
                              ↓ 据此修订
第三轮（复杂程序）→ 首轮通过  → 4 个规避行为全部消失
                              → 但又暴露 2 处新空白
                              ↓ 已据此再次修订
```

**每一轮都「通过」，但每一轮都能找出新的空白。**
这说明：**用 Agent 的实际行为来检验文档，比通读文档找漏洞有效得多**——
Agent 会把「资料里没写」精确地暴露成「我不得不绕路」，
而通读文档只会让人得出「该写的都写了」的错觉。

（原计划三轮即可收尾，实际到第二轮已足以证明修订有效；
第三轮留下的 2 处空白已补入指南，可在后续使用中继续观察。）
