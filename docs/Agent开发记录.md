## 记录一：验证 AI 开发指南的有效性

**日期**：2026-10-09

**目的**：检验 `docs/AI开发指南.md` 与 `skills/willen/SKILL.md` 是否足以让
一个**完全不了解 Willen 的编程 Agent** 首轮写出可运行的代码。

### 实验设计

| 项 | 设置 |
|---|---|
| Agent 类型 | 通用编程 Agent（general-purpose） |
| 提供的上下文 | **仅** `skills/willen/SKILL.md` 的正文内容 |
| 明确禁止 | 读取项目中的任何其他文件（`docs/`、`tests/`、`src/`、`examples/`） |
| 任务 | 猜数字游戏：随机数 1–100、循环输入、大小提示、计数、非法输入处理 |
| 规模要求 | 不少于 25 行（不含空行），带中文注释 |

**为什么必须禁止读其他文件**：项目里的 `tests/` 有 12 个模块的测试集，
`docs/Willen语言规范.md` 有完整规范——Agent 若读了它们，就无法判断结果
是「指南有效」还是「资料足够多」。**只有把资料限制到指南本身，
测出来的才是指南的有效性。**

### Agent 的产出

`apps/猜数字.wl`，62 行（要求 25 行）：

```willen
# 猜数字游戏
# 程序先随机生成一个 1 到 100 的目标数，然后不断让玩家猜测，
# 每次给出「大了」「小了」的提示，猜中后统计并输出猜测次数。

# 判断一个字符串是否全部由数字字符组成。
# 因为 整数() 遇到非数字内容会直接报错，所以必须先自行检查。
函数 是数字串(甲) {
    如果 (长度(甲) == 0) { 返回 假 }
    设 数字表 = "0123456789"
    设 游标 = 0
    当 (游标 < 长度(甲)) {
        如果 (非 数字表.包含(甲.字符(游标))) {
            返回 假
        }
        游标 = 游标 + 1
    }
    返回 真
}

# 随机数两端都包含，所以 随机数(1, 100) 就是 1 到 100 之间的整数
设 目标 = 随机数(1, 100)

# 有效猜测次数，非法输入不计入
设 次数 = 0

# 主循环：反复提示输入，直到猜中才跳出
当 (真) {
    设 行 = 输入("请输入 1-100 的数字：")

    # 去掉首尾空白，避免玩家多打了空格导致误判
    设 文本 = 行.去空白()

    # 情况一：不是纯数字，提示后重新输入，次数不增加
    如果 (非 是数字串(文本)) {
        打印("输入的不是数字，请重新输入")
        继续
    }

    设 猜 = 整数(文本)

    # 情况二：数字超出了 1 到 100 的范围，同样视为无效输入
    如果 (猜 < 1 或 猜 > 100) {
        打印("数字超出范围，请输入 1-100 的数字")
        继续
    }

    # 到这里才算一次有效猜测
    次数 = 次数 + 1

    如果 (猜 > 目标) {
        打印("大了")
    } 否则如果 (猜 < 目标) {
        打印("小了")
    } 否则 {
        打印("猜中了！")
        跳出
    }
}

# 猜中后结束，输出总次数
打印("你一共猜了 {次数} 次")
```

### 验证过程与结果

| 检查项 | 命令 | 结果 |
|---|---|---|
| 语法正确 | `willen ast apps/猜数字.wl` | 通过，无语法错误 |
| 基本运行 | 喂入 1..100 | 正常猜中并退出，退出码 0 |
| 非法输入（非数字） | 先喂 `abc` | 提示「输入的不是数字，请重新输入」 |
| 非法输入（超范围） | 再喂 `200` | 提示「数字超出范围，请输入 1-100 的数字」 |
| 计数准确性 | 上述非法输入 | 均未计入有效次数 |

**首轮通过率：1 / 1 = 100%**

### 指南硬性规则的遵守情况

逐条核对指南第 1 节的八条规则：

| # | 规则 | 是否遵守 |
|---|---|---|

### 值得记录的细节：Agent 写出了指南没教、但更好的写法

我在指南 §4.6 给的输入校验模板是逐字符比较：

```willen
遍历 (字 在 文本) {
    如果 (字 < "0" 或 字 > "9") { 返回 空 }
}
```

Agent 写的是：

```willen
设 数字表 = "0123456789"
当 (游标 < 长度(甲)) {
    如果 (非 数字表.包含(甲.字符(游标))) { 返回 假 }
    游标 = 游标 + 1
}
```

用字符串的 `包含` 与 `字符` 做成员判断。**这比我的模板更稳**——
逐字符比较依赖字符串比较的语义，而 `包含` 是在一个明确的字符集里查找，
意图更直接、边界更清楚。

这说明指南没有限制住 Agent 的表达：它能在规则之内自行选出更好的实现方式。
这是好现象——**指南约束的是「不能写什么」，而不是「必须怎么写」。**

### 结论

**指南有效。** 一个没有任何 Willen 先验知识的 Agent，仅凭 `SKILL.md`
就首轮写出了语法正确、功能完整、边界处理妥当的代码。

这条结论有实际意义：它说明 Willen 的语法设计对机器足够友好——
规则数量少、上下文无关、无歧义，因此能被准确描述，也能被准确实现。
