# Willen 解释器架构说明

## 整体数据流

```
源码 .wl
   ↓  lexer.cpp        把文本切成词法单元（Token）
词法单元序列
   ↓  parser.cpp       递归下降组装成语法树（AST）
语法树
   ↓  interp.cpp       遍历求值
运行结果
```

## 模块职责与规模

| 文件 | 职责 | 行数 |
|---|---|---|
| `token.h` | 词法单元类型、`Token` 结构、中文关键字表 | 51 |
| `lexer.h` / `lexer.cpp` | 词法分析：源码 → Token 流 | 440 |
| `ast.h` | 语法树节点定义（17 种表达式 + 12 种语句） | 89 |
| `ast_dump.cpp` | 语法树的 S 表达式输出（调试与测试比对用） | 174 |
| `parser.h` / `parser.cpp` | 语法分析：游标、表达式优先级阶梯 | 454 |
| `parser_stmt.cpp` | 语句解析（声明、控制流、函数、结构体） | 249 |
| `value.h` / `value.cpp` | 值类型系统、打印格式、深度比较 | 203 |
| `interp.h` / `interp.cpp` | 作用域链、运行入口、表达式求值 | 395 |
| `interp_stmt.cpp` | 语句执行、函数调用、赋值 | 196 |
| `builtins.h` / `builtins.cpp` | 全局内置函数与数组/字符串方法 | 402 |
| `main.cpp` | 命令行：`run` / `lex` / `ast` / `repl` | 208 |

每个源文件都在 500 行以内。

## 关键设计决策

### 1. 中文关键字是怎么实现的

`lexer.cpp` 里标识符的判定规则只有一行关键：

```cpp
return std::isalpha(u) || c == '_' || u >= 0x80;
```

UTF-8 把一个汉字编码成 3 个字节，**每个字节都 ≥ 0x80**。规则放宽到接受非 ASCII
字节后，`设`、`斐波那契` 就和 `if`、`foo` 一样被当作完整标识符读入，
之后查同一张关键字哈希表。

所以：**中文关键字不需要任何特殊处理**，本质是「标识符规则放宽 + 哈希表」。

### 2. 表达式优先级靠调用层次表达

`parser.cpp` 里没有优先级数字表，而是一条调用链：

```
assignment → logicOr → logicAnd → equality → comparison
           → range → term → factor → unary → postfix → primary
```

低优先级的运算符位于调用栈更外层，因此天然后结合。
**读代码时看到的调用链，就是优先级表本身。**

### 3. 条件的括号是强制的

必须写成 `如果 (条件) { ... }`。原因：`如果 甲 { }` 里的 `甲 {`
与结构字面量 `点{横: 1}` 的写法**完全一致**，解析器无从区分二者。
强制括号把这个歧义在语法层面直接消除，递归下降不需要任何回溯。

这不是理论担忧——实现过程中真的踩到过：报错后若继续按原样解析，
`甲 {` 会被当成结构字面量，进而报出一串与真正原因无关的级联错误。

### 4. 模板字符串在解析期降解

`"你好，{名字}！"` 的处理分两步：

1. **词法阶段**：切成「文本片段 / 插值表达式源码 / 文本片段」的序列
2. **解析阶段**：插值片段被**递归送进词法 + 语法分析器**，变成子 AST 节点

因此运行时求值模板只剩字符串拼接，完全不碰字符串解析。

### 5. 控制流用返回值传递，不用异常

`exec` 返回 `Flow` 枚举：`Normal / Break / Continue / Return`。
循环消费 `Break` 与 `Continue`，函数体消费 `Return`——
**所以 `跳出` 不会穿出函数边界**，函数里的 `跳出` 不会意外跳出调用它的循环。

### 6. 不做闭包

函数一律登记在顶层的函数表里，调用时新建栈帧，且**父环境是全局而非调用点**：
函数看不见调用者的局部变量。省掉了 upvalue 机制，
函数调用只剩「新栈帧 + 参数绑定 + 执行函数体」三件事。

### 7. 引用语义与深度比较

- 数组与结构体用 `shared_ptr` 共享底层对象：赋值与传参只复制指针，
  对内容的修改在所有引用处可见（引用语义）
- 而 `==` 对它们做**递归深度比较**，所以 `[1,2] == [1,2]` 得 真

### 8. 真值判断不做隐式转换

只有 `假` 与 `空` 为假。`0`、空字符串、空数组一律为真。
隐式转换是脚本语言里最常见的坑，这里干脆不做。

### 9. 错误传播

运行时错误抛出 `RuntimeError{消息, 行号}`，由 `run()` 统一接住并打印成
`第 N 行：<中文说明>`。这不是语言层面的异常机制（Willen 没有 try/catch），
只是 C++ 内部传递错误的手段——任何一层出错都不必逐层检查返回值。

## 扩展点

| 想加什么 | 需要改哪里 |
|---|---|
| 新关键字 | `token.h` 加枚举值 → `lexer.cpp` 的 `KEYWORDS` 表加一行 |
| 新运算符 | `token.h` → `lexer.cpp` 扫描分支 → `parser.cpp` 对应的优先级层次 → `interp.cpp` 求值 |
| 新内置函数 | `builtins.cpp` 的 `callBuiltin` 加一个分支 |
| 新对象方法 | `builtins.cpp` 的 `callMethod` 加一个分支 |
| 新语句类型 | `ast.h` 加节点 → `parser_stmt.cpp` 解析 → `interp_stmt.cpp` 执行 → `ast_dump.cpp` 打印 |
